# 星月计划 · 南极星实验室：完整引导式配置

需求确认：2026-09-05。沿用现有 Electron / React 外壳，不另造一套桌面 UI。

项目名称已由用户确定为“星月计划”（Project Star & Moon）。界面借鉴用户参考图的留白、月相、靛蓝/淡紫与细金弧线，以原创 SVG 几何构图实现。每一步的弧面、月相和轨道连续变形；前进时有限时长的光轨向前行进，返回时反向，静止时不循环跑动画。系统“减少动态效果”启用时关闭光轨和位移。保留南极星实验室署名，不直接使用参考插画的人物、作品名称或原图作为项目标志。

当前实施边界：欢迎、六语选择、可选星标和语言持久化已接入开发副本；下列完整连接分支、后端验收回执和毕业页还没有全部接线。不能把这份设计当成已完成的端到端配置工具。

## 产品口吻与基本规则

欢迎语：

> 你好，欢迎来到南极星实验室。
> 这是我们的双向工作台项目：把 ChatGPT 网页与本地 Codex 连接起来，让云端协作与受控的本地工作环境相互配合。
> 不用一次弄懂所有术语。接下来，我们一步一步来。

六种语言：简体中文、English、Français、日本語、Русский、Deutsch。首次问候可以参考系统语言；接着明确请用户确认语言，不能把自动检测当作用户选择。之后始终尊重用户已保存的选择。翻译词条要求完整，技术协议名、模型 ID、错误代码和原始诊断信息不应翻译得无法检索。

每页固定有：本步做什么、为什么需要、要准备什么、具体操作、当前检测结果、失败后怎么办、返回、下一步和稍后继续。高风险变更另列出影响范围和撤销方法。不会让用户为了进入软件而必须登录、付费、点赞或授权主机全盘访问；跳过必需配置时进入“尚未完成”的工作台，相关功能保持未启用。

帮助可展开，但普通路径一次只展示当前要做的一件事。中文长句、德语长词、俄文字母、键盘焦点和小窗口滚动均须验收。平台原生授权窗口由用户自己处理，不能伪造“已允许”。

## 两条连接必须分开讲

1. **网页推理与 Native2 工具回传通道**：本地 Codex 使用 Chat 网页推理，工具调用回到原来的 Codex 回合。保留原桥现有方式，避免回调与作业调度互相阻塞。
2. **Work 远程作业通道**：Work 通过独立网关提交、查询、取消本地任务。只暴露受授权的作业接口，不直接开放任意 shell、全盘文件或桌面控制。

界面分别显示服务名称、所属账号、地址、认证状态和用途。不能把同一个地址盲目填到两个入口，也不能将 Native2 短期回合凭证当作 Work 的长期控制凭证。

## 连接分支 A：临时 HTTPS 地址

适合先试用、不想先买域名的人。用户原 kit 使用 Cloudflare 临时 Tunnel；可以复用其部署经验，但不在新 UI 旁边再添加竞争的服务管理者。

逐页引导：

1. 解释临时地址会变化，没有长期可用保证，适合测试。
2. 检查将要发布的是专用任务网关，绑定回环地址，并已具备认证。未保护的通用本地控制接口不许发布。
3. 识别现有 AgentDock/Tunnel 服务归属；可复用时展示“连接现有服务”，不能自动重装或替换健康服务。
4. 用户确认后，仅启动本程序拥有的临时连接，显示分配的 HTTPS 地址。
5. 检查公网 TLS、未登录访问的拒绝结果、认证元数据和授权流程。
6. 检查真实 MCP 传输与工具发现。Cloudflare Quick Tunnel 不支持 SSE，因此依赖 SSE 的实现不能在该分支伪装成功；只有经实测支持的非 SSE 路径才允许继续。没有合适路径就引导改用固定域名或其他隧道。
7. 帮用户添加 Work 连接器，执行合成任务并查询结果。
8. 地址变化后醒目提示“需要重新连接”，使旧地址验证过期；解释哪些设置需要更新，不要求重新做所有安装步骤。

Cloudflare 官方将 Quick Tunnel 定位为测试/开发用途，不保证 SLA；注明不支持 SSE，并有并发请求上限。[官方限制](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)

## 连接分支 B：固定域名 + Cloudflare Tunnel

适合准备长期使用、希望地址稳定的人。将“是否已有域名”“注册域名的费用”“Cloudflare 服务计划”分别解释。不是必须购买 Cloudflare 付费套餐，也不要求在某一家注册商购买域名。

逐页引导：

1. 询问是否已有可管理的域名。没有时先介绍选择，并提供返回免费试用路径；不自动下单。
2. 引导在 Cloudflare 添加并管理该域名，说明 DNS/NS 变更可能影响已有网站和邮件。不得不加区分地覆盖现有记录。
3. 创建命名 Tunnel，用户在服务商页面完成登录和授权。
4. 将 Tunnel Token 存入平台私有凭据存储，不放聊天、截图、日志或子任务目录。
5. 选择一个专用子域名，绑定到经过认证的本地任务网关；保留其他网站路由。
6. 检查域名解析、HTTPS、隧道连接、身份验证和真实 MCP 传输。
7. 完成 Work 插件授权和演练。若额外 Cloudflare Access 登录墙与连接器不兼容，使用已验证的服务身份方案，不能简单关掉所有认证。

固定公开主机名需要 Cloudflare 账号和相应域名配置；发布应用本身不要求付费的 Cloudflare Access 计划。[配置要求](https://developers.cloudflare.com/tunnel/setup/)、[计划说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/)

## 连接分支 C：自己的 VPS

标注“进阶，需要维护服务器”，不默认推荐用户额外购买 VPS。

逐页引导：

1. 判断用户已有还是准备购买 VPS；说明持续费用、维护、系统升级和公网暴露责任。
2. 让用户确认目标服务器身份、操作系统和 SSH 主机指纹，使用独立密钥登录。没有可验证权限则停在此页，不索取密码到聊天。
3. 检查现有 Web 服务和端口，生成拟变更清单，不覆盖原站点。
4. 选择固定域名并配置 HTTPS 反向代理，只发布任务网关路由。
5. 建立 VPS 到本地的受认证隧道。反向监听优先绑定 VPS 回环，由 HTTPS 入口访问；不直接开放本机命令端口。
6. 配置必要防火墙规则、认证、请求限制和流式响应设置；不清空防火墙，也不关闭 TLS 校验。
7. 检查实际网络路径、证书、拒绝匿名访问、MCP 传输、断线重连和账号授权。
8. 执行 Work 到本地的真实演练，并提供“停止”“撤销本次配置”和“维护清单”。

具体代理/隧道工具及发行版命令要在选定实现后按其官方文档固化并真机验收；此阶段不生成一条不分系统、直接在所有 VPS 上执行的安装脚本。

## 真正完成后的页面

先显示有范围的结论，例如：“Codex 网页模型已验证；Work 调度未启用”。只有用户选择的能力都通过，才显示对应的完成祝福；不能拿模拟回执、工具列表或 HTTP 200 充当整条链路成功。

完整双向至少验证：运行时、工作区权限、账号、真实模型往返、控制面认证、MCP 传输、工具回调，以及 Work 提交任务后取得一致的结果。还要检查取消真正停止、重复提交不重复执行。

`launcher/src/setup-readiness.ts` 已建立前端就绪判定契约：不接受模拟、失败、未知、过期、未来时间或另一套配置的回执。真正安全边界仍在主进程/网关，后续必须由它们签发实测结果；仅靠前端布尔值不能证明权限或执行。
