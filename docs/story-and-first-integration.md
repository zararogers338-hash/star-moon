# 星月计划：先让桥接通，再让故事发生

2026-09-05。产品与实施提案，不是已经完成的能力清单。

## 当前事实

- 星月界面仍来自原 Electron/React 外壳；云月切换、六语、模式命名和配置引导改造不等于融合后端完成。
- 已在本地研究副本核对用户 `chatgpt-local-mcp-kit` 的 README：它复用了 AgentDock、HTTPS 隧道、OAuth、安装／检查／修复脚本和可选 Coding Agent 入口，是部署与接入套件，不是我们自行实现的 MCP 核心。
- 原网页桥的 MCP 是 Native2 工具回传路径；用户套件是网页访问本机的路径。两者保留独立处理通道和凭据域，避免父任务等待时阻塞子任务必须使用的工具回传。
- 相邻 `duplex-workbench/src/local-demo.ts` 仍使用 `SimulationRunner`；`codex-turn.ts` 明确只提供协议适配，没有接到模拟网关。没有真实 Work → Codex → 网页推理 → 本地工具 → Work 的验收。
- 本次核对的是本地已有代码基线，不宣称已拉取各仓库最新版本。不改动现有 AgentDock 服务、账号、隧道或正常 Codex 配置。

## 下一阶段开发顺序

暂停新增纯装饰功能，优先完成一个小而真实的闭环。

1. **接入用户 MCP 套件。** 增加独立 `agentdock-adapter`，先以外部已有服务方式对接健康检查、认证发现和版本／能力信息；把安装、检查、修复路径纳入同一个引导。默认只读检查，不为了“试一下”重启健康服务或更换临时地址。随后再做受管安装，每个服务只能有一个生命周期管理者。
2. **接通真实任务执行。** 将受管 Codex worker 接到作业网关，先使用一次性测试工作目录；网页只得到提交、状态、取消和授权产物接口。命令、任意路径工具、动态工具发现不得成为绕过策略的入口。未验证平台隔离前不宣传“安全沙箱”。
3. **网页端真实验收。** 使用用户确认的账号与授权入口连接；若现有 AgentDock 不支持受限工具注册或可靠转发，则保留独立网关端点，不强行共用一个服务。Work 仍在网页使用，且必须实测该账号能否调用连接器；未通过时如实停在未连接状态。
4. **形成第一个闭环。** 合成 CSV → 网页提交分析要求 → 本地生成统计程序并测试 → 返回报告、测试结果与文件校验值。必须在网页核对返回内容与本地产物一致；仅工具发现、HTTP 200、模型说“完成”均不放行。
5. **再完善六语和四类安装包。** 包括 Windows、macOS、Linux DEB、Linux RPM；各平台的服务管理和隔离机制单独验收，不能因生成安装文件就声明兼容。

工程关口：真实提交先持久化并立即返回；幂等提交不重复执行；取消核实子进程停止；拒绝越界访问；认证失效不循环重试；结果未知的写入不自动重放；远端模型不能批准自己的扩权。真实登录、系统权限与公网入口变更由用户在需要时确认。

## 故事核心

> 让远方的月光，照进你自己的工作间。

用户不是来学习一整套基础设施的，而是循着远方的一点光，来到南极星实验室，亲手看着月亮升起、亮起，然后决定要在这片夜色里走多远。软件的角色是向导与工作台，不是要求用户接受一套复杂设定。故事用真实变化推进，不靠堆名词。

按用户确定的顺序，叙事主线收束为：**来到这里 → 月亮升起 → 月亮亮起 → 永夜 → 落幕**。这是同一个故事的推进，不是五个新功能名；“接力”和“守夜”是故事中发生的行为，不再增加并列章节。

| 阶段 | 人能理解的经历 | 必须兑现的行为 |
| --- | --- | --- |
| 来到这里 | 你循着一点光，来到南极星实验室。我们说：“你好，我的朋友。” | 选择语言与月色；解释这是什么、会访问什么、哪些可跳过 |
| 月亮升起 | 你亲眼看着自己的工作间一点点搭好。“不必急，我们一起，让月亮慢慢升起来。” | 一页一页检查环境、登录与授权；需要代理协助时可走“明月初次升起”入口、寄出月夜信。现阶段该协助入口仍待实现 |
| 月亮亮起 | “云端与本地，在此相遇。”第一条真实请求带着结果返回，月光照进工作间 | 验证 MCP、受控执行与返回产物；连接状态的光轨只由真实验收驱动，不能用装饰性月亮或主题切换冒充连接成功 |
| 永夜 | 月亮似乎永远也不会落下。你已经能够工作，也可以自愿继续探索更长的上下文 | 提供实验性 3× Chat 上下文选项，说明风险与适用范围；默认关闭、可跳过，不把故事做成必须开启实验功能的门槛 |
| 落幕 | 完成的作品被带回桌前。“今晚的故事，先写到这里。月光留下，明天再见。” | 展示文件、变更、测试、未验证项与可恢复的进度。用户决定何时结束；活动任务仍在执行时不得画成全部结束。若选择“守夜”，明确是后台继续，并非停止 |

“明月／暗月”是同一工作间的两种光线，不是权限等级。“守夜”只表示关窗后继续后台运行。“永夜”仍是实验性 3× 上下文的名字，不承诺无限记忆、无限时间或额外额度。

### 永夜的固定文案层级

**永夜**  
月亮似乎永远也不会落下  
实验性 · 开启 3× Chat 上下文

最后一行用小字，位于诗句下方；设置页和推荐弹层顺序相同。用户所说的“三倍 Chat 用量”按代码中的真实功能解释为上下文处理范围：`src/chatgpt-web-models.ts` 将相应上下文／压缩阈值乘以 3，传输层按需拆分消息；不是给账号增加三倍使用额度。风险、重启要求和默认关闭的说明仍保留。没有因此改动运行时限制或开启开关。

“你已经学会了”的安装毕业是**这段故事可以开始了**，不是故事的落幕；落幕属于用户一次真实工作的结束。下次再来可以从留下的进度继续，不必重演整套欢迎仪式。跳过永夜也必须能完整交付和结束。

## 值得加的三件事

1. **会说实话的旅程图。** 只用少量位置点显示网页、本地与执行环境；光轨由真实作业事件驱动。待授权、断线、暂停与完成可一眼分清，仍配普通文字且支持减少动态效果。它不是装饰性进度条，也不把三个位置画成已经实现的三层虚拟机。
2. **能接手的月夜信。** 信只包含脱敏环境事实、已通过步骤、当前障碍、日志摘要和下一步。可选短时、一次性配对连接到受限本地网页控制面；信本身不是授权书。默认回环绑定，校验来源、权限与令牌过期；停止接管立即撤销。登录、提权、扩权不由代理替用户确认，秘密不进入信件。
3. **一张清楚的交付卡片。** 每次任务列出产物、实际测试、执行位置、模型路由与仍未验证的部分。提供检查差异、接收修改、打开文件；需要回退时说明哪些可恢复，不承诺撤销所有外部操作。无需再给它起专属诗名。

文案分层：章节可以有温度；操作按钮、权限、错误、日志和预算必须直白。六语翻译传达同样体验，不逐字堆砌中文典故。失败不是用户“太笨”，而是向导应该解释和帮助恢复的状态。

结尾保留用户的祝福，但只在真实验收完成后出现：

> 你已经学会了。接下来，请尽情探索吧。祝你好运，祝你有好心情，我的朋友。

此提案承接既有《双向工作台：架构与实施计划》，不改变其权限、账号、隔离与发布验收边界。
